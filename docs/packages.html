Packages

butter-col is published as npm packages under the @axis-network scope. The packages come from the npm workspaces in this repository.

Overview

PackageWhat it isYou need it to…
@axis-network/butter-colThe proxy: service worker, runtime, formatter, ButterController, the built-in butter transport, the Lua server and the butter-col CLIRun butter-col
@axis-network/butter-transportThe transport API: types, registry, TransportError, testing kitWrite a transport
@axis-network/bare-transportTransport for TompHTTP Bare v3 serversUse a Bare server as the backend

All three are ES modules, MIT-licensed, and require Node 20 or newer for the tooling. The browser files they ship work in Chrome/Edge 100+, Firefox 102+ and Safari 15.4+.

@axis-network/butter-transport

npm install @axis-network/butter-transport

This is the only dependency a transport needs. It provides registerTransport, createTransport, validateTransport, TransportError, header helpers and the TypeScript types. @axis-network/butter-transport/testing adds smokeTest. The full reference is on Build a transport.

@axis-network/bare-transport

npm install @axis-network/bare-transport
npx butter-col transport add @axis-network/bare-transport
  • dist/bare-transport.js (also exported as ./browser) is the script to serve.
  • The main entry exports createBareTransport and its helpers without registering anything.

Options are documented on Transports.

A new project

mkdir my-proxy && cd my-proxy
npm init -y
npm install @axis-network/butter-col @axis-network/bare-transport

npx butter-col transport add @axis-network/bare-transport
cp node_modules/@axis-network/butter-col/server/config.lua butter.config.lua   # then edit it
npx butter-col server start --site public

The first server start downloads the CA bundle. It renders everything into .butter/: the nginx config, logs, cacert.pem and the served transports. Add .butter/ to .gitignore, and commit butter.config.lua, butter-transports/ and your site.

OpenResty must be installed. On Windows, unzip openresty-<version>-win64.zip into .tools/ in the project (or a parent directory), or pass --openresty.

CLI reference

butter-col server start [options]
Render the config into the runtime directory, copy the transports into it, download the CA bundle if it's missing, and run OpenResty in the foreground. Ctrl+C stops it.
butter-col server reload | test | stop [options]
reload re-renders the config and reloads without dropping connections; cookie jars survive. test re-renders and runs nginx -t. stop stops the server. Pass the same options you started with.
butter-col fetch-ca [--runtime .butter]
Download Mozilla's CA bundle (via curl.se) to <runtime>/cacert.pem.
butter-col transport add <package-or-file> [--name n] [--transports dir]
Copy a transport's browser script to butter-transports/<name>.js. The name comes from the package's "butter.transport" field, or from --name.
butter-col transport list
Show the built-in and added transports.
butter-col static <outdir> [--config butter.static.json] [--site dir]
Build a serverless deployment.
butter-col paths
Print the package's paths as JSON.

ButterController

The page-side API, for launchers and your own UI:

import { ButterController } from "/butter/controller.mjs";

const butter = await new ButterController({
  serviceWorker: "/butter/sw.js",   // defaults shown
  scope: "/",
  config: "/butter/config.js",
  searchEngine: "https://duckduckgo.com/?q=%s",
}).init();

butter.go("example.com");                     // navigate through the proxy
butter.encodeUrl("https://example.com/");     // → "https://proxy/butter/go/https%3A%2F%2Fexample.com%2F"
butter.decodeUrl(location.href);
butter.resolveInput("cute butter");           // → search URL

butter.transports;                            // [{ name, url, options }] from the config
await butter.getTransport();                  // { active: { name, url, options }, available: [{ name, url, loaded }] }
await butter.setTransport("bare", { server: "https://bare.example.com/" });
await butter.resetTransport();

init() rejects with a readable message if the browser has no service workers or the page isn't a secure context. All transport calls go to the service worker over a MessageChannel.

Serverless deployments

With a transport that doesn't need butter-col's server (bare today), butter-col can be deployed as static files to GitHub Pages, Netlify, Cloudflare Pages, S3 and so on:

// butter.static.json
{
  "prefix": "/butter/go/",
  "codec": "xor",
  "transports": [
    { "name": "bare", "options": { "server": "https://bare.example.com/" } }
  ],
  "defaultTransport": "bare"
}
npx butter-col transport add @axis-network/bare-transport
npx butter-col static public --config butter.static.json --site my-site

The output:

public/
  index.html app.js app.css your site (or the frontend)
  404.html                  bootstrap page: static hosts serve it for /butter/go/… URLs
  butter/sw.js client.js controller.mjs formatter.mjs bootstrap.html
  butter/config.js          generated from butter.static.json
  butter/transports/        butter.js + everything in butter-transports/
  • HTTPS: serve over HTTPS.
  • Service worker scope: the service worker registers with scope /, which requires the header Service-Worker-Allowed: / on /butter/sw.js. Hosts that can't set headers can register with scope: "/butter/" instead (new ButterController({ scope: "/butter/" })); the bootstrap page falls back to it automatically. Proxied pages and their requests still work. The difference is that a navigation that escaped rewriting to a path outside /butter/ reaches the host instead of the service worker.
  • Cookies: with no server, document.cookie and all cookies are kept by the service worker's client jar, so pick "client" cookie transports.
  • Hosts that return 404: some static hosts send the 404.html page with status 404, which is fine. The bootstrap installs the service worker and reloads, and the service worker answers from then on.

With Express

If you'd rather serve the files from Node than from OpenResty, pair the static config with a transport that doesn't need the Lua server:

import express from "express";
import { distPath, createPublicConfig, createConfigScript } from "@axis-network/butter-col";

const config = createPublicConfig({
  transports: [{ name: "bare", url: "/butter/transports/bare.js", options: { server: "/bare/" } }],
});

const app = express();
app.get("/butter/config.js", (req, res) => res.type("js").send(createConfigScript(config)));
app.get("/butter/sw.js", (req, res) => {
  res.set("Service-Worker-Allowed", "/").sendFile("sw.js", { root: distPath });
});
app.use("/butter/transports/", express.static("butter-transports"));
app.use("/butter/", express.static(distPath));
app.use("/butter/go/", (req, res) => res.sendFile("bootstrap.html", { root: distPath }));
// mount a Bare server at /bare/ (e.g. @tomphttp/bare-server-node) and your site at /
app.listen(8080);
The built-in butter transport, its cookie jar and its SSRF guard live in the Lua server. Under Express you only get what your transport's backend provides.

The packages were created with npm init --scope=@axis-network inside the workspace. From the root:

CommandDoes
npm installLinks the workspaces together
npm run buildBuilds every package in dependency order
npm test · npm run test:luaRuns the JS and Lua tests

To add a package, run npm init -w ./packages/<name> --scope=@axis-network, then copy the publishConfig, exports and files conventions from an existing package.

Releasing

  1. Bump the versions. Bump @axis-network/butter-transport first if its API changed, and keep the dependent packages' ^ ranges in step.
  2. Run npm run check.
  3. Publish in dependency order: npm publish -w @axis-network/butter-transport, then -w @axis-network/butter-col, then -w @axis-network/bare-transport. Each package has publishConfig.access = "public", because scoped packages are private by default.
  4. Check the published contents with npm pack --dry-run -w <package> before the first release.
