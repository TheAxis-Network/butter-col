Credits

butter-col wouldn't exist without the people who showed that a whole website can run inside a service worker. The idea for this project comes straight from their work.

Mercury Workshop

For Scramjet, the interception proxy that set the modern bar for this kind of project: rewriting JavaScript properly, handling the awkward corners of the web platform, and being taken seriously as software. Also for Wisp, epoxy, libcurl.js and bare-mux, which showed how far a proxy transport can go. butter-col's pluggable transports, and switching them at runtime with setTransport, follow the idea bare-mux brought to Scramjet.

  • github.com/MercuryWorkshop
  • Scramjet

Titanium Network

For Ultraviolet, which made the service-worker web proxy an everyday tool, and for the community that grew around it. butter-col's xor codec uses the same scheme as Ultraviolet's. The built-in transport protocol borrows the shape of Bare: targets and headers in request headers, the real status and headers in response headers. @axis-network/bare-transport implements the Bare v3 client side from the TompHTTP specification, so butter-col can use existing Bare servers.

  • github.com/titaniumnetwork-dev
  • Ultraviolet
butter-col is an independent project. It is not affiliated with or endorsed by Mercury Workshop or Titanium Network, and it contains no code from their projects. Everything here was written from scratch, inspired by their designs. Any bugs are entirely ours. If you need a proven, maintained proxy today, use theirs.

Specifications

The Fetch, HTML and Service Workers standards, and RFC 6265 (cookies). The bad-port list, referrer policies, cookie date parsing and much of the tokenizer behaviour follow them directly. The TompHTTP specifications (Bare server v2/v3 and its error codes) define what @axis-network/bare-transport speaks.
