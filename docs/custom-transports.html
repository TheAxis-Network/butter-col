Build a transport

A transport is one factory function that returns an object with meta, request() and optionally connect(). This page covers everything else: where it runs, what it may and may not touch, and how to package, test and publish it.

Quick start

  1. Copy examples/transport-template to a new folder. Rename it in package.json, both "name" and "butter.transport.name", and in the registerTransport() call.
  2. Replace the logic in src/index.js (or switch to TypeScript; the types ship with @axis-network/butter-transport).
  3. Run npm run build to produce dist/<name>-transport.js, one classic script.
  4. In a butter-col project: npx butter-col transport add ./path/to/your-transport (a package name or a .js file both work).
  5. Add { name = "yours", options = { … } } to transports in butter.config.lua and reload the server.
  6. Pick it in the launcher's transport menu, or with butter.setTransport("yours").

The smallest transport

This one forwards to a server with its own simple protocol. Everything here is required except connect():

import { registerTransport, TransportError } from "@axis-network/butter-transport";

registerTransport("tiny", (options, env) => {
  const endpoint = new URL(options.endpoint, env.origin).href;

  return {
    meta: { name: "tiny", cookies: "client", websockets: false },

    async request(req) {
      let res;
      try {
        res = await env.fetch(endpoint, {
          method: "POST",
          headers: { "content-type": "application/json" },
          body: JSON.stringify({
            url: req.url.href,
            method: req.method,
            headers: req.headers,
            body: req.body ? btoa(String.fromCharCode(...new Uint8Array(req.body))) : null,
          }),
          signal: req.signal,
        });
      } catch {
        throw new TransportError("TRANSPORT_UNREACHABLE", "The tiny server is down.");
      }
      const meta = JSON.parse(res.headers.get("x-tiny-meta"));
      return { status: meta.status, statusText: meta.statusText, headers: meta.headers, body: res.body };
    },
  };
});

The base64 body encoding is only there to keep the example short. Real transports should stream or send the raw ArrayBuffer.

Lifecycle

  1. Load. butter-col loads your script in every realm that might need it:
    • the service worker, with importScripts during startup;
    • every proxied page, with an injected <script>;
    • every proxied worker, through the prelude.
    At the top level your script should only call registerTransport(). Do no work and make no network calls.
  2. Create. When a realm first needs a transport, it calls your factory with the options and an environment. The service worker does this on the first proxied request, and a page on the first new WebSocket(). butter-col validates the returned object, then awaits init() if you defined one.
  3. Use. In the service worker, request() is called for every HTTP request of every proxied tab. It runs concurrently, so it must not keep per-request state on the transport object. In pages and workers, connect() is called for each WebSocket.
  4. Switch. When the visitor switches transports, the old instance's destroy() is called in the service worker. Instances in already-open pages live until those pages unload.

One deployment might create your transport in a dozen realms at once. Keep the factory cheap, and keep init() idempotent.

Factory & options

type TransportFactory<Options> =
  (options: Options, env: TransportEnvironment) => ButterTransport | Promise<ButterTransport>;

options comes from the deployment's configuration, or from the visitor's setTransport(name, options). Because both are public, the visitor can supply anything:

  • Validate the options, and throw a clear TypeError when something required is missing.
  • Accept relative URLs and resolve them against env.origin, as both bundled transports do. That way the same configuration works on any host.
  • Never require a secret. Anything in the options can be read from /butter/config.js.

The environment

FieldMeaning
env.scope"serviceworker", "window" or "worker".
env.originThe proxy's own origin.
env.configThe full public configuration: prefix, codec, endpoints, the transport list.
env.fetchThe unhooked fetch.
env.WebSocketThe unhooked WebSocket constructor (may be missing in a service worker).
Always use env.fetch and env.WebSocket, never the globals. In pages and workers, butter-col replaces window.fetch (it rewrites URLs) and window.WebSocket (it routes through your connect()). Calling the global WebSocket from inside connect() recurses forever.

meta

FieldRequiredMeaning
nameyesMust equal the registered name: lower-case letters, digits, ., _, -, at most 64 characters.
cookiesyes"server" if your backend keeps cookies, otherwise "client". See Cookies.
websocketsyestrue only if connect() is implemented.
version, descriptionnoShown in logs and tools.

request()

request(req: TransportRequest): Promise<TransportResponse>

You receive:

FieldMeaning
urlAbsolute http:/https: URL, fragment removed.
methodThe page's method.
headersLower-case names, one value each. Already contains the right referer, origin and sec-fetch-*, plus cookie for "client" transports. Send them as they are.
bodyArrayBuffer, or null for GET and HEAD.
signalAborted when the page cancels. Pass it on.
context.destination, context.modeFrom the intercepted Request, for transports that want to prioritise or cache.
context.wantDocumentCookiesFor "server" transports: return the document.cookie view in documentCookies.

You return:

FieldMeaning
statusThe upstream status, 200–599. Don't follow redirects yourself: return the 3xx with its location header, and butter-col rewrites it.
statusTextOptional reason phrase.
headers[name, value] pairs in order, with one pair per set-cookie (don't join them!). Use headersToList() to convert from Headers or an object.
bodyThe decoded body as a ReadableStream, ArrayBuffer, Blob, string, or null. If your backend sends compressed bytes, either let the browser decompress them (send Content-Encoding on your own HTTP response, as butter and bare do) or decompress them yourself.
documentCookiesOnly for "server" transports, and only when asked.

butter-col then drops hop-by-hop, CSP and other unsafe headers, rewrites Location, Link and Refresh, and rewrites HTML, CSS and JS bodies according to the request destination. Return the upstream response as faithfully as you can.

Errors

Throw a TransportError(code, message, status?). The visitor sees the code and message on butter-col's error page, which uses status (default 502) as its HTTP status. Use the standard codes where they fit, so error pages and docs stay consistent:

ConstantCodeWhen
UNREACHABLETRANSPORT_UNREACHABLEYour backend can't be reached.
BAD_RESPONSEBAD_TRANSPORT_RESPONSEYour backend answered with nonsense.
DNS_FAILUREDNS_FAILUREThe target's host doesn't resolve.
UPSTREAM_UNREACHABLEUPSTREAM_UNREACHABLEThe target refused or reset the connection, or TLS failed.
UPSTREAM_TIMEOUTUPSTREAM_TIMEOUTThe target was too slow.
BLOCKEDBLOCKEDYour backend refuses this target.
ERRORTRANSPORT_ERRORAnything else.

Prefix your own codes (for example BARE_UNKNOWN). Re-throw AbortError unchanged, because butter-col treats it as a cancelled request rather than an error. Error objects are matched by shape (TransportError.is()), so it doesn't matter that every transport bundles its own copy of the class.

connect()

connect(url: URL, protocols: string[], headers: HeaderMap, handlers: SocketHandlers): TransportSocket

This is called inside the page or worker. butter-col's own WebSocket class already validated the URL, so url is always ws: or wss:. headers holds origin (the page's target origin), user-agent, and cookie for "client" transports. Return synchronously, then report progress:

HandlerCall it when
handlers.open(protocol, extensions)The upstream handshake succeeded.
handlers.message(data)A frame arrived: string for text, ArrayBuffer or Blob for binary. butter-col converts to the page's binaryType.
handlers.error(message)Something failed. Follow it with close().
handlers.close(code, reason, wasClean)The connection is gone. Call it exactly once; use 1006 when it never opened.
handlers.cookies(setCookies)Optional, for "client" transports that see the handshake's Set-Cookie values.

The returned socket needs send(data) and close(code?, reason?), and may expose bufferedAmount. butter-col only calls send() after open, and enforces the close-code rules before calling close().

Cookies

meta.cookies = "server"
Your backend stores cookies, for example per session as butter-col's Lua server does. butter-col never adds Cookie and ignores Set-Cookie. For documents it sets context.wantDocumentCookies, and you should return documentCookies: the non-HttpOnly cookies for that URL, joined with "; ". Script writes to document.cookie are POSTed to config.transport.cookie (/butter/cookie), so your backend needs that endpoint. If you can't provide it, use "client" mode.
meta.cookies = "client"
butter-col keeps the jar in the service worker. You receive cookie in req.headers; send it on. You return every set-cookie pair; butter-col stores them. Nothing else is needed, because document.cookie and WebSocket cookies are handled for you.

Rules of the road

  • Top level: do nothing at the top level except registerTransport(). Your script runs in every proxied page, before the page's own code.
  • Globals: don't touch page globals, and don't add your own. The page can see them.
  • Native APIs: use env.fetch and env.WebSocket (see the environment).
  • Concurrency: request() runs concurrently and must be re-entrant.
  • Redirects: don't follow them, and don't add or rewrite headers on purpose. butter-col computes the right request headers and expects the raw upstream response.
  • Destinations: enforce your own policy, such as private-network blocking, on whatever server does the outbound connections. The browser side can't be trusted to do it.
  • Size: keep the bundle small. It loads into every proxied document.
  • Script format: build an IIFE with no import/export at the top level, because the same file is loaded with importScripts() and with import in module workers.

Packaging

A transport package needs two things:

  • a browser script that registers the transport;
  • a "butter" field telling tools where that script is.
{
  "name": "@your-scope/thing-transport",
  "version": "1.0.0",
  "type": "module",
  "main": "./dist/index.js",
  "exports": {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" },
    "./browser": "./dist/thing-transport.js"
  },
  "butter": {
    "transport": { "name": "thing", "browser": "dist/thing-transport.js" }
  },
  "files": ["dist"],
  "dependencies": { "@axis-network/butter-transport": "^0.1.0" }
}

The recommended layout, which @axis-network/bare-transport uses:

  • src/index.ts exports createThingTransport(options, env) with no side effects, for tests and for people composing transports.
  • src/register.ts calls registerTransport("thing", createThingTransport).
  • esbuild bundles register.ts as an IIFE (dist/thing-transport.js) and index.ts as ESM.

Bundle @axis-network/butter-transport into the IIFE. The registry is a single global, so separately bundled copies share it.

Testing

Unit tests

Call your factory directly with a fake environment and a mocked fetch, as packages/bare-transport/test/bare.test.mjs does:

const env = { scope: "serviceworker", origin: "https://proxy.test", config, fetch: mockFetch, WebSocket: FakeWebSocket };
const transport = createThingTransport({ endpoint: "/thing" }, env);
const res = await transport.request({ url: new URL("https://example.com/"), method: "GET",
  headers: {}, body: null, context: { destination: "", mode: "cors", wantDocumentCookies: false } });

Smoke test

@axis-network/butter-transport/testing checks the shape, a real request, and optionally a WebSocket echo:

import { smokeTest } from "@axis-network/butter-transport/testing";

const report = await smokeTest(transport, {
  url: "https://example.com/",
  websocketUrl: "wss://echo.websocket.org/",
});
console.table(report.checks); // shape, status, headers, body, websocket

Because transports are plain scripts, you can even load the built browser file into Node (vm.runInThisContext) and smoke-test it against a running server. butter-col's own transports were checked that way.

In the browser

Add it with butter-col transport add, select it in the launcher, open DevTools and watch the service worker's console. Wrapping your transport with the logged template prints every request.

Publishing

npm run build
npm publish --access public   # scoped packages are private by default

Official Axis Network transports are published under the @axis-network scope. Community transports should use their own scope or name, ideally ending in -transport, and include the butter-transport keyword so others can find them.

Checklist

  • meta.name matches the registered name and package.json's butter.transport.name.
  • meta.cookies is right, and "server" transports return documentCookies and handle /butter/cookie.
  • meta.websockets is true only if connect() exists.
  • Only env.fetch and env.WebSocket are used.
  • Redirects aren't followed; set-cookie pairs aren't joined; bodies are decoded.
  • Failures throw TransportError with a standard code; AbortError is re-thrown.
  • connect() calls close exactly once, including when the connection never opened.
  • The browser bundle is an IIFE, small, and has no top-level side effects beyond registering.
  • smokeTest passes.

API reference

Everything below is exported from @axis-network/butter-transport.

registerTransport(name, factory)
Register a factory in this realm's global registry. A second registration under the same name replaces the first, with a console warning.
createTransport(name, options, env) → Promise<ButterTransport>
Call the factory, validate the result, check meta.name and await init(). butter-col uses this in every realm, and wrapping transports use it to create their inner transport.
getTransportFactory(name) · listTransports()
Look up the registry.
validateTransport(object) → string[]
Structural problems; an empty array means the object is valid.
TransportError(code, message, status = 502) · TransportError.is(value) · TRANSPORT_ERROR_CODES
See Errors.
headersToList(headers) · listToObject(list) · readBody(body)
Helpers. headersToList keeps Set-Cookie values apart (it uses Headers.getSetCookie()), and readBody reads any response body type into an ArrayBuffer.
Types
ButterTransport, TransportFactory, TransportEnvironment, TransportMeta, TransportRequest, TransportRequestContext, TransportResponse, SocketHandlers, TransportSocket, HeaderMap, HeaderList, ButterPublicConfig, TransportEntry, TransportScope.
@axis-network/butter-transport/testing → smokeTest(transport, { url, websocketUrl?, timeout? })
Returns { ok, checks: [{ name, ok, detail }] }.

Ideas

  • Wisp: wrap Mercury Workshop's epoxy-tls or libcurl.js so TLS ends in the browser and the server only relays TCP. This would be a "client" cookie transport.
  • Failover: try a list of inner transports in order, like the logged wrapper but switching on TRANSPORT_UNREACHABLE.
  • Racing: send idempotent GETs to two backends and keep the first answer.
  • Caching: keep immutable responses in the Cache API, keyed by URL, using context.destination to decide what to cache.
  • Direct: fetch CORS-enabled APIs straight from the browser and fall back to another transport for the rest.
